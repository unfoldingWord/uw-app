# The app ships English content inside it

On 2026-11-06 the requirements owner decided that the app ships with the English content and Open Bible Stories built in, all of it: the English default Language Pack, the stories and their helps, and the Image Pack, so a fresh install reads offline with no download (PRD decision 105, ON-5, `docs/proposals/2026-11-06-english-inside-the-app.md`). We made the app's own binary a fourth pack source, `bundled`, beside the catalog, a peer and a file, rather than a second way for content to arrive: the carried content is the same Door43 burrito archives, pinned by release and sha256 in a committed lock (`content/bundled.lock.json`), fetched and verified by `npm run bundled:fetch` on every native build, carried as Metro assets, read through a Bundled port and installed by `packs.placeBundled()` through the one install path (ADR 0005), so checksums, provenance, atomic replacement and events are unchanged. A table, `bundled_packs`, remembers every carried pack that has been on the phone, so a leader who removes English never gets it back unasked, and a catalog update replaces a carried release like any other (LA-7). This is hard to reverse because every installed phone records burritos whose source is `bundled`, journals that replay them, and leaders who never downloaded English; taking it out later means a release that leaves those phones without content they never chose to download. The cost: about 71 MB more in the app binary for every leader, including those who never read English, a phone that holds both the archives in the binary and the unpacked packs (about 347 MB after first launch, measured in the sim and estimated for the binary), a lock to refresh when English releases move (a weekly job reports drift), and builds that need Door43 to be reachable. A replayed journal places from the replaying device's Bundled port, so a phone's placement replays only where that port carries the same archives.
