# Files reach the app through the Picker port and reach screens through media addresses

Two device facts had no port. First, SH-3 asks the app to import a burrito the leader opens from a file, and asking the system for a file is a device API. We decided on a Picker port (`pickArchive()`), with `expo-document-picker` as its platform adapter and a scripted memory adapter, and `packs.importPicked` adopting what it returns into the one install path (ADR 0005); being offered for a `.zip` another app opens needs native document types, an Android `VIEW` intent filter and Expo Router's `+native-intent` hook, which is not a route and so is not a one-line re-export. Second, story frames and cached impact story images are Files paths, and a screen needs an address to render one. We decided that the Files port gains one synchronous read, `uriOf(path)`, and that a `media` kernel module that owns nothing answers it only for files under `packs/` (outside the staging and inbox directories) and `partners/images/`; a web address is never loaded as a picture, so a screen cannot fetch anything by rendering. The costs are an eleventh port, native configuration in `app.config.ts` that only a phone can prove, and a media address that is a platform detail (`file://` on a phone, a blob address in the render harness) the sim can check only for presence. Accepted in issue #6; proposals `docs/proposals/2026-09-29-file-import.md` and `docs/proposals/2026-09-29-media-addresses.md`.
