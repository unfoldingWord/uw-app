# One audio player in the kernel

ST-4 asks for an audio bar that plays, pauses and seeks, and FO-3's "Play and discuss" plays story audio where it exists. The Audio port had both adapters but no kernel module used it, and a screen may not call a port. We decided on one `player` kernel module that owns nothing and drives the Audio port through the kernel's allowlisted wrapper: one clip at a time, a file only under `packs/` (outside dot directories), port calls in order so an overlapping load never leaves an older clip loaded, and a status (`idle`, `loading`, `playing`, `paused`, `ended`, or `failed` with a code) read synchronously with `subscribe`. It stops when the pack holding its clip is removed. It emits no event of its own and keeps no snapshot: listening is not counted (PRD 9 has no such fold) and the position never enters the journal; the only entry is a `Failure` with step `audio`, so a replay names that failure as a divergence. `clipControls` gives the study and formation services one clip's toggle, seek, skip and stop. Audio is download-only in v1.0.0 (ST-4, issue #53): the port's `url` source is refused by nothing today but used by nothing either. The cost is that playback is proven only against the memory adapter's scripted clock until a phone runs `expo-audio`. Accepted in issue #6; proposal `docs/proposals/2026-09-29-audio-player.md`.
