# Exceptions

Every exception to rules 1 to 4 of [`AGENTS.md`](../AGENTS.md), written before the code, in the same commit
(rule 5). An exception without an entry here is a defect. Newest first.

| 2026-09-29 | Content contract: a burrito outside the pinned rows is ignored | `src/lib/packs/burrito.ts` (`packRows`), `sim/fixtures/rows.ts` (`fixtureRows`), `scripts/contract.ts` | `validate` admits only `pinnedRows` unless it is handed rows. While the proposal `docs/proposals/2026-09-29-provisional-flavors.md` is pending, the app installs the three provisional rows too, through one named constant, `packRows = admittedRows`, so formation, audio and image packs can be installed and proven in the sim (FO-2, FO-5, ST-4, LA-3, LA-4). The fixtures and the contract check of fixture burritos pass `fixtureRows`; the live contract check passes only `pinnedRows`. Closes when DCS pins each form or the proposal is refused; then `packRows` and `fixtureRows` become `pinnedRows`. |
| 2026-09-29 | Rule 4: `src/lib/kernel.ts` is a shared root, changed only through a proposal | `src/lib/kernel.ts` (`kernelModules`), `sim/kernel.test.ts` (the registry pin) | Architecture.md fixes eight module slots (Catalog, Packs, Corpus, Formation, Transfer, Share, Journal, Strings) plus Telemetry, but a slot can only be listed once its module exists, and each arrives in its own task of the scaffold PR. Until the scaffold PR merges, each of those tasks adds its one line to `kernelModules` and to the pin in `sim/kernel.test.ts`, and nothing else in `kernel.ts`. Listed today: telemetry, catalog, packs, corpus, formation, strings (Journal is part of the kernel itself). Pending: transfer, share. Closes when the scaffold PR merges; after that a new module is an architecture change with a proposal. |
| 2026-09-29 | Rule 2: `sim/*` imports `src/lib/*` and `src/features/*/service.ts` and nothing else | `sim/migrations.ts` | Migrations are discovered by reserved location (`migrations/` and `src/features/*/migrations/`, AGENTS.md rule 4), never listed in a registry, so the sim finds them by reading those directories and loading each file by its path. A migration file is data: an id and SQL statements, typed by `import type { Migration } from '@lib/ports'`, and the `migrations` lint layer in `scripts/eslint/boundaries.ts` refuses any other import in it. The sim loads nothing else this way. |
| 2026-09-29 | Rule 1: a new content flavor starts as a row in `docs/content-contract.md`, then a fixture burrito, then Corpus | `src/lib/burrito/flavors.ts` (`provisionalFlavors`, the three `provisional` rows), `sim/fixtures/releases.ts` | Upstream has not pinned the burrito form of the five-movement formation content, audio or the story images, so no contract row can be written yet, and FO-2, FO-5, ST-4, LA-3 and LA-4 need fixture burritos to be proven in the sim. The three flavors are provisional names behind one exported constant, reported with `status: 'provisional'`, and refused as unknown by the validator unless the provisional rows are passed to it by name (see the entry above). Proposal: `docs/proposals/2026-09-29-provisional-flavors.md`. Closes when DCS pins each form or the proposal is refused. |
| 2026-09-29 | Rule 2: application code reaches a device API only through a port | `src/shared/glass/**`, `src/shared/fonts/useThemeFonts.ts` | The glass primitives import `expo-blur` (`BlurView`, `BlurTargetView`), `expo-haptics` (press feedback), React Native's `StatusBar` with `react-native-safe-area-context`, and `expo-font` (`useFonts`) directly. AGENTS.md section 3 lists Blur, Fonts and Haptics as rendering modules with no port, and the sim never renders, so a port would carry a memory adapter that does nothing. The imports stay inside `src/shared/glass` and `src/shared/fonts`; features and screens reach them only through the primitives and `useThemeFonts`. |
| 2026-09-29 | Rule 2: a relative import never leaves its unit | `src/shared/fonts/assets.ts`, `tsconfig.json` | AGENTS.md section 3 says the fonts come from `design-system/assets/fonts/` and nowhere else, so the binaries are not copied into `src/`. `src/shared/fonts/assets.ts` imports them through a `@design-system/assets/fonts/*` path alias added to `tsconfig.json`, scoped to that one folder so nothing else under `design-system/` is importable. `src/shared/fonts/font-files.d.ts` types a `.ttf` import as the asset id Metro returns. |
| 2026-09-29 | AGENTS.md section 7: a value that is not in the tokens is a design change | `src/shared/glass/referenceValues.ts` | The reference components in `design-system/components/glass/*.jsx` carry literals that are not tokens: button and chip padding, the chip's night fill and border, the solid and dark button borders, the refraction opacity, the ring's geometry and 4.5 s breathe, the aurora's 18 percent overscan and 22 s drift, the filament's geometry, the icon's 20 px and 1.7 stroke defaults, and the 40 percent disabled opacity from `readme.md`. They are copied verbatim into one named record so each is traceable to its source and none is invented; promoting them to tokens is a Claude Design change. |
| 2026-09-29 | AGENTS.md section 7: React Native primitives keep the names and props of `design-system/components/glass/*.d.ts` | `src/shared/glass/*.tsx` | Names are kept. Props with no React Native meaning are mapped, dropped or added: `style` is a React Native style, not CSS; `GlassSurface` drops `as` and `radius` takes a number instead of a CSS length; `GlassButton`, `GlassIconButton` and `GlassInput` take React Native `Pressable` and `TextInput` props instead of HTML attributes (`onPress`, `onChangeText`); `GlassButton` requires `accessibilityLabel` when its children are not a string and `GlassInput` always requires it, so every control has an accessible name (section 7); `GlassButton` and `GlassIconButton` add `busy` so a control can go busy before its first `await` (section 10); `GlassInput` has no default placeholder, since copy lives in the string table; `Icon` has no CSS `currentColor`, so it defaults to the colour of the surface or control it sits in, and mirrors its directional glyphs in right-to-left layouts; `StatusBar` is a fake iOS status row for mockups, so it becomes a safe-area spacer that sets the system status bar style, and drops `time`. |
| 2026-09-29 | Rule 2: `src/platform/*` never imports application code | `src/platform/**` | A platform adapter implements a port, so it must see the port's interface and the domain types that interface names. `src/platform/**` may import `@lib/ports` and `@lib/domain/*` as types only (`import type`), which erase at build and carry no behaviour. Every value import from `@lib`, and every import from `@features`, `@shared` or `@sim`, stays refused. Enforced by the `platform` layer in `scripts/eslint/boundaries.ts` with `allowTypeImports`. |
